# 콘테스트 플레이북 — 99designs · 라우드소싱

콘테스트 엔트리를 만들고 제출할 때 지키는 규칙. 실행 방법은
`routines/contest-entry.md`, 렌더 경로는 `docs/REMOTE_RENDER.md`를 본다.

> 플랫폼 약관은 바뀐다. 제출 직전에 콘테스트 브리프와 플랫폼 고객센터의 최신
> 안내를 다시 읽는다. 이 문서는 그때 확인할 항목을 고정한다.

## 1. 기본 원칙

- 플랫폼이 요구한 이미지·장수·비율·형식은 **그대로** 올린다. 미리보기 링크나
  목업으로 대체하지 않는다.
- 제출 단계에서는 플랫폼이 요구한 형식만 올린다(보통 PNG/JPG, 로고는 벡터일 수
  있다). 요구하지 않은 편집 원본(SVG·AI·PDF)은 수상·결제 전에 넘기지 않는다.
- 엔트리·미리보기·프로필 어디에도 연락처를 넣지 않는다. 이메일, 전화, SNS,
  메신저 ID, QR이 해당한다. 포트폴리오 URL은 플랫폼 정책이 예외로 두는 경우가
  있지만, 우리는 내부 원칙으로 넣지 않는다.
- 같은 작품을 서로 다른 콘테스트에 재사용하지 않는다(내부 원칙). 플랫폼은
  참여작이 독창적이고 제3자 권리를 침해하지 않는다고 요구한다.

## 3. 파일 이름 규칙

팩 안의 파일 이름은 그래프가 정한다. 사람이 붙이는 이름은 브리프·런 기록에 쓴다.

```
<platform>_<brand-slug>_<profile>_<seed>
예: 99designs_sonagi-tea_web_4f2a1c
```

- `platform`은 소문자 슬러그(`99designs`, `loudsourcing`).
- `brand-slug`는 공백 없이(`sonagi-tea`).
- `profile`은 `web`·`print`·`brand`.
- `seed`는 `spec.seed`. 입력이 같으면 자동 seed도 같다. 입력을 바꿔 재실행할 때
  같은 값을 고정하면 계보를 유지할 수 있다.

팩 파일 이름은 profile마다 다르다. web은 `<variant-id>.png`·`.jpg`, print는
`<id>-front.png`·`<id>.jpg`, brand는 `mark-<width>.png`·`mark.jpg`다. 제출 화면에서
이름을 바꿔야 하면 플랫폼 규칙을 따르되, 로컬 팩과 manifest는 원래 이름을 보존한다.

## 4. 보존

| 대상 | 보존 |
|---|---|
| 제출한 팩 (`pack/` 안의 `entry.md` 포함, `manifest.json`) | 수상 결과가 나올 때까지 삭제 금지 |
| 수상작 팩 | 영구 보관. 외부 아카이브에 `manifest.json`과 함께 복사 |
| 탈락작 팩 | 플랫폼 약관의 사용 제한 확인 후 정리. 내부 기준 30일은 로컬 보관 |
| 제출 기록 | thread_id, run_id, manifest digest, 플랫폼 URL, 제출 시각 |

- 배포의 `/home/ubuntu/entry_pack`(또는 `SONAGI_OUT_ROOT`·`SONAGI_ENTRY_OUT`)은
  자동 정리되지 않는다. 디스크가 차면 오래된 런부터 지우되, 제출·수상 팩은 먼저
  다른 경로로 옮긴다.
- `show`가 출력하는 manifest의 `sha256`·`digest`와 `manifest_digest`를 기록한다.
  이 값이 "무엇을 냈는지"를 증명하는 핵심 기록이다. 팩만 복사하고 manifest를
  빠뜨리지 않는다.
- 원본 SVG는 수상 전까지 공개 저장소·CDN에 올리지 않는다.

## 5. 외부 링크 주의

- 엔트리 이미지·설명·댓글에 포트폴리오, 노션, 드라이브, 개인 사이트 링크를 넣지
  않는다. 플랫폼은 이를 외부 거래 유도로 볼 수 있다.
- 미리보기 링크는 내부 리뷰용으로만 쓴다. 플랫폼이 요구한 이미지를 대신하지
  않으며, 제출 화면에는 올리지 않는다.
- 링크가 꼭 필요한 콘테스트라면 브리프에 허용 여부가 적혀 있는지 먼저 확인한다.
  허용되지 않았으면 텍스트 설명으로 대체한다.
- QR 코드도 연락처·외부 링크와 같게 취급한다.

## 6. 제출 전 체크리스트

- [ ] 콘테스트 브리프의 필수 이미지·장수·비율·형식을 다시 읽었다
- [ ] print·brand: `meta.json`의 `gates_ok`가 `true`이고 `ok: false` gate가 없다
- [ ] brand: `pdf: false`가 아니라면 `mark.pdf`가 있다 (`brand.pdf` skipped는 정상)
- [ ] web: `items` 수가 승인한 selection 수와 같고 PNG/JPG가 0바이트가 아니다
- [ ] print: entry 모드는 재단 크기·레이어·바코드·렌더 크기 gate를, handoff 모드는 도련·PDF gate를 통과했다
- [ ] brand: `outlined.svg`에 텍스트·스타일이 없고 아이콘 크기가 모두 있다
- [ ] `entry.md`의 방향·스타일·테마가 브리프와 맞는다
- [ ] 이미지에 이메일·전화·SNS·QR·외부 URL이 없다
- [ ] 플랫폼이 요구한 이미지를 모두 준비했다 (미리보기 링크로 대체하지 않았다)
- [ ] 플랫폼이 요구하지 않은 원본 파일은 올리지 않았다
- [ ] 생성형 AI 사용 여부를 플랫폼 절차대로 밝혔다
- [ ] 제출할 팩과 `manifest.json`을 백업했다
- [ ] thread_id·run_id·digest·플랫폼 URL을 기록했다

## 7. 제출 후

1. 플랫폼에서 수정 요청이 오면 같은 `spec.seed`로 재실행해 계보를 유지한다.
2. 수상하면 원본 전달 절차를 플랫폼 안에서만 진행한다.
3. 탈락하면 팩을 바로 지우지 말고, 플랫폼의 비사용 조항과 내부 보존 기간을 확인한다.
4. 같은 브랜드로 다음 콘테스트를 준비할 때는 이전 팩의 `entry.md`와 `meta.json`을
   읽어 방향이 겹치지 않게 한다.
